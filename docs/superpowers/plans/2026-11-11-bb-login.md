# Bookie Bashing login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** When the Scraper finds its Bookie Bashing page logged out, it logs in itself with Callum's own login from the Scraper's `.env`, once, and carries on.

**Why:** Callum, 11 Nov 2026: "bb will need to be able to login". Today a logout stops `bb-saves` until a person logs in on the Hub's screen.

**Architecture:** One new module, `scraper/login.py`, holds the site's login form (selectors taken from the real page), reads the credentials from the environment, drives the form on the page that is already open, and keeps a small "last attempt failed" note on disk. `scraper/runner.py` calls it at the two places that find a `needs_login` site logged out, before the alert and back-off. No new page load is made to log in: the logged-out page already carries the form.

**Spec:** this file (the change is small; there is no separate design document).

## Review Focus

1. **A wrong password must not be retried.** Logged out, attempt made, the next read still logged out: one alert, the usual back-off, and no second attempt at any later logout, including after a new `Runner` is built on the same data directory.
2. **A lapsed subscription looks like a logout** (the tool redirects to `/how-it-works` while logged in, and the page then has no login link). That must end as a failed attempt ("no login form"), not a loop.
3. **The site's error text may echo what was typed.** Any text taken from the page into a log or alert has the password and the username removed first.
4. **No credentials set**: nothing in today's behaviour changes; no new log lines.
5. **The form is slow or the page is mid-navigation**: `attempt` never raises and never hangs past its timeout.

**Interfaces — produces:**

```python
# scraper/login.py
@dataclass(frozen=True)
class Form:
    user_env: str; pass_env: str
    opener: str; form: str; user: str; password: str; remember: str; submit: str; error: str

FORMS: dict[str, Form]            # {"bookiebashing": Form("BB_USERNAME", "BB_PASSWORD", ...)}
NOTE_FILE = "login.json"          # <data>/login.json  {"<site>": {"failed_at": <epoch>, "why": "<text>"}}
WHY_MAX = 120

def credentials(site: str, env=os.environ) -> tuple[str, str] | None
    # None unless the site has a Form and both variables are set and non-blank (stripped).
def attempt(page, site: str, creds: tuple[str, str], timeout_s: float = 20.0) -> str | None
    # Open the pop-up if the form is not visible, fill both fields, tick "remember me",
    # press the button, then wait (within timeout_s) for the page to navigate or the
    # form to go, or for the site's refusal text.
    # Returns None when the form was sent and no refusal was shown.
    # Returns a short reason otherwise: "no login form", "refused: <site text>", or
    # "<ExceptionClass>" for anything unexpected. Never raises. The reason is scrubbed
    # of both credentials and cut to WHY_MAX.
def failed(data_dir, site: str) -> dict | None      # the note, or None; a corrupt file reads as None
def mark_failed(data_dir, site: str, why: str, now: float) -> None   # never raises
def clear(data_dir, site: str) -> None              # never raises
```

**Runner behaviour** (`scraper/runner.py`):
- At both places that set `reason = "logged out"` for a `needs_login` site, first call a new `Runner._try_login(site, tab, now) -> bool`. When it returns True the logout is not reported: no alert, no back-off; the tab is set to reload its own tool URL at the next tick through the normal guard and spacing (use the existing `due_at` mechanism).
- `_try_login` returns False, and does nothing, when: `login.credentials(site)` is None; or `login.failed(data_dir, site)` is set.
- `_try_login` when an attempt for this site is already waiting on its next read (`self.login_pending[site]`): the login did not hold. `mark_failed(..., "still logged out after signing in")`, drop the pending mark, return False.
- Otherwise it calls `login.attempt`. Reason returned: `mark_failed` with it, return False. None returned: set `self.login_pending[site] = now`, write `"logged out - signing in"` to the job's log with `self._say`, return True.
- When `_try_login` has just marked a failure, the one alert that `_on_blocked` sends for the logout says so: `"bookiebashing: logged out on <url> - signing in failed (<why>). Not trying again until you log in on the Hub's screen or run `resume bookiebashing`. Backing off."` (over VNC wording in a container, as today). With no failure note the alert is today's text. Still one alert per logout.
- When a `needs_login` site is next read logged in (`_on_clear`): drop `login_pending[site]`, `login.clear(data_dir, site)`, and if an attempt had been pending write `"signed in"` to the job's log.
- A page that `browser.blocked()` reports is handled as today and never reaches `_try_login`.

**CLI** (`scraper/__main__.py`): `resume <site>` also calls `login.clear(data_dir, site)`, and for a site with a login form the printed line ends with " A failed sign-in is forgotten: it will try once more at the next logout."
