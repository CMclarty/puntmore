# Finder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Finder, the owner-only private Bet Finder board on the me subdomain: Render keeps, serves and expires the bets Hermes posts from the Hub; the placer reads them; the Hub's tip intake feeds Hermes instead of the removed wire.

**Architecture:** On Render a new package `app/finder/` (one table, a status machine, a sweep), a router at `/api/finder/*` (two key-authenticated POSTs from the Hub, two grant-guarded GETs), a private `finder` source in the cross-tool value feed, and a `/finder` page gated to the new `me` site. On the Hub the inbox stops queuing `tip` messages, a `puntmore finder` CLI gives Hermes the new tips and posts its verdicts, and the link daemon runs the inbox and mail loops without a socket.

**Tech Stack:** FastAPI, SQLAlchemy, APScheduler, pytest (`render/api`); React + Vite + vitest (`render/frontend`); the Hub's stdlib Python + pytest (`hub/`).

**Spec:** `docs/finder-spec.md` (binding; `docs/decisions.md` wins over it).

## Global Constraints

- Owner-only: the board and every Finder route sit behind the new `finder` tool grant; Finder is never in the combined `GET /api/value` and never readable by the `value` grant.
- The Hub posts with the `ingest` grant (`require_ingest_key` in `app/routers/saves_ingest.py`); rows and statuses never come in on a session.
- Status words, exactly: `asked`, `offered`, `rejected`, `placed`, `gone`, `expired`. `asked → offered | rejected | expired`; `offered → placed | gone | expired`; `placed`, `gone`, `rejected`, `expired` are final. A re-post that would move a final row is refused with 409.
- One live bet per `(event_id or event, market, selection)`: a second row while one is `asked` or `offered` is stored `rejected`, reason `duplicate of <tip_id>`.
- `edge = odds / fair - 1` (the `ValueSelection` meaning). A row with no `fair` can only be `asked`.
- `expires_at` = the earlier of `kickoff` and the tip's own `expiry`; Render sets `expired` on its own clock, every minute.
- Retention 30 days from `created_at`.
- Render never loads a page and spends no OddsPapi request on a tip.
- `hub/` changes are limited to Task 7's files; the Hub's `mock_render`, protocol tests and placement code are untouched.
- Commit messages end with the two attribution lines this session uses (`Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`, `Claude-Session: https://claude.ai/code/session_013jCUTuGdz9ogpzSZnRywMB`). Branch `integration-2` in `/home/callum/Projects/puntmore-int2`.
- Test commands: API `cd render/api && /home/callum/Projects/puntmore/api/.venv/bin/python -m pytest tests/ -q`; frontend `cd render/frontend && npm run lint && npm test && npm run build`; hub `cd hub && ~/.venvs/puntmore/bin/python -m pytest -q`.

## Review Focus

1. A tip posted twice with the same `tip_id` after the placer has placed it: the second post must not reopen it (409, row unchanged). (Task 3)
2. Two tipsters sending the same bet in different words: the second becomes `rejected` as a duplicate, never a second `offered` row. (Task 3)
3. A Hermes post with `status: offered` but no `fair`: stored `asked`, never offered. (Task 3)
4. A key that holds `ingest` but not `finder` can post rows and cannot read the feed or the board; a session with `finder` can read both and cannot post. (Task 4)

**Interfaces:**
- Produces, in `app/finder/rows.py`:
  - `STATUSES = ("asked", "offered", "rejected", "placed", "gone", "expired")`, `FINAL = frozenset({"rejected", "placed", "gone", "expired"})`
  - `class RowIn(TypedDict)`-style plain dict keys accepted by `upsert`: `tip_id, origin, sport ("football"|"horse"), bookmaker, event, home?, away?, event_id?, kickoff (aware UTC), market, selection, line?, side?, odds, fair?, advised_stake?, reason?, status ("asked"|"offered"|"rejected"), expiry? (aware UTC)`
  - `upsert(db, rows: list[dict], now: datetime) -> dict` → `{"stored": n, "updated": n, "refused": [(tip_id, reason)], "duplicates": [tip_id]}`; computes `edge`, `expires_at = min(kickoff, expiry)`, forces `asked` when `fair is None`, applies the duplicate rule, refuses (lists under `refused`) a post against a final row.
  - `set_status(db, tip_id, status: str, at: datetime) -> FinderRow`; raises `ValueError("final")` on a final row, `KeyError` on unknown, `ValueError("status")` if `status` not in `("placed", "gone")`.
  - `expire(db, now) -> int` (rows `asked|offered` with `expires_at <= now` → `expired`).
  - `feed(db, now) -> list[FinderRow]` (`offered`, `expires_at > now`, soonest `kickoff` first).
  - `board(db, since: datetime) -> list[FinderRow]` (all statuses, `created_at >= since`, newest first).
  - `sweep(db, now, days: int = 30) -> int`.
- `FinderRow` columns: `tip_id` (PK), `origin`, `sport`, `bookmaker`, `event`, `home`, `away`, `event_id`, `kickoff`, `market`, `selection`, `line`, `side`, `odds`, `fair`, `edge`, `advised_stake`, `reason`, `status`, `expires_at`, `asked_at`, `answered_at`, `seen_at`, `created_at`, `updated_at`; times naive UTC like the rest of `models.py`.
